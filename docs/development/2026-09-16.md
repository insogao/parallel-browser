## Reviewer 复核后的加固（同日追加，未改写前一提交）

- **P1 异步窗口转移**：capture 保活 setup 发 `normal` 后有界等待 `windowState===normal` 才发 park 位置，并有界校验位置实际生效后才记录 `parked`；超时/未生效会 warn。cleanup 不再靠一次严格等值探针静默跳过：只要仍持有控制权，就按“恢复到 original position（normal 状态下）→ 最小化”修复并用有界探针验证 `minimized`，失败 warn 而不是把前台窗口静默留给用户。fake CDP 新增“每次 setWindowBounds 后第一个 getWindowBounds 仍返回旧状态/旧 frame”的延迟模式；新增确定性测试证明仍按 original position→minimized 顺序清理且 `hideApp` 恰好一次。
- **P2 pid 绑定与接管竞态**：`appHidden`/`hideApp` 改为接收 engage 时绑定的 managed pid（`getContext()` 增加 `pid`），浏览器重启不会误操作新实例；新增 `unhideApp`，延迟 hide 完成后重查 `allowed()`，若 takeover 已开始则补 unhide（顺序断言 `['hide','unhide']`），保证人工接管最终可见。takeover 优先用例保留。
- **P2 windows.ts**：等待 `normal` 超时直接返回 false，**不发送 maximize**；`restoreAll` 在计数前复查 `isControlCurrent(gen)`，supersede 不计 `restored`。新增“永远 minimized 不发 maximize”“supersede 不计恢复”两项确定性单元。
- **P2 验收脚本**：`app-control`/`swiftc` 的 `execFileSync` 增加 timeout；清理不再用 `pkill -f <tmp>`（裸正则风险），改为 `ps -axo pid=,args=` 精确匹配临时 profile 路径后按已知 pid SIGTERM/SIGKILL；signal/异常 finally 保持不变。
- **文档口径**：PROJECT_INDEX 明确列出指标只来自 Phase A（capture 关闭），避免读成最终 capture 验收已通过。

## Reviewer 第二轮复核 P1 修复（同日追加）

- **修复标志**：在向窗口发送 `normal` 之前设置 `windowTouched`；finally 的修复门槛不再依赖 `parked`。即使 normal 验证失败或 park 从未记录，只要仍是同一 cdp/pid 且未被 takeover，就执行 `original position → minimized` 的 best-effort 修复；读探针持续失败时仍发送恢复命令并 warn/计失败（与 setup 失败去重，避免同一事件双计）。
- **探针重试**：`waitForWindowState`/`waitForWindowPosition` 对单次 `getWindowBounds` 失败继续有界重试，只有 attempts 用尽、上下文失效或窗口消失才失败；新增 `readWindowBoundsBounded` 用于 cleanup/takeover 的多次重探。
- **normal 未就绪不再继续 setup**：抛出进入现有 catch，failure/cooldown 正常累计；finally 仍修复窗口。
- **takeover 清理**：单探针失败改为有界重探；仍不可读时 warn 并安全尝试恢复 original position，不会把窗口静默留在 offscreen。
- **新增确定性单测（红→绿）**：normal 后所有探针 reject → setup 不成功、cleanup 仍发送 original position→minimized、hidden app 恰好 re-hide 一次、无 controller/标题残留；normal 后单次瞬时 reject → 重试后 setup 仍成功。两项在旧源码上失败。
- **剩余风险**：capture 的 hide/unhide 不走 proxy 的 native 可见性队列（见 PROJECT_INDEX 能力边界）；`setPaused(true)` 等待 + cleanup 的 allowed/unhide 保证 `/api/show` 接管可见，但 capture 与 API 的 native 操作并发时无全局串行保证。手动移动窗口/Dock 恢复应经 `show` 路由，避免与 capture setup 并发操作同一窗口。

## 能力边界

- `document.visibilityState` 只读上报，capture 豁免下由 Chromium 决定显示值，不做断言也不改写（本次最小化+capture 时报 `visible`）。
- 补偿 rAF（shim）只证明页面逻辑帧，不代表原生合成帧；原生 compositor rAF 单独采集。无 capture 时原生 =0.0/s、shim 58.5/s 的对照来自同日 Phase A 运行。
- capture 的 hide/unhide 不共享 proxy 的 native 可见性队列；`setPaused(true)` 等待 + cleanup 的 allowed/unhide 保证 `/api/show` 接管最终可见，但 capture 与 API 的 native 操作并发时无全局串行保证。手动移动窗口或 Dock 恢复应经 `show` 路由，不要与 capture setup 并发操作同一窗口。

## Launcher reviewer 加固（同日追加）

针对独立复查的三项中等加固：

- `runLogin`：先只读解析引擎选择；受管会话正以其他引擎运行时直接返回 `{ok:false, mismatchedEngine:true, restored:0}`，不改 settings、不动 `humanMode`/capture、不 maximize/activate/launch/kill；启动失败回滚 `humanMode` 与 capture 暂停状态（控制代际有意保留）。`launcher-unit.ts` 逐项断言零副作用与失败回滚。
- 安装锁 `launcher-install.lock`（owner.json：pid/token/startedAt）：`installRuntime`/`installLauncher` 串行；陈旧锁（owner 死亡/无元数据 >3s）用原子 rename 到唯一 tombstone 接管，release 校验 token；不抢占存活 owner，避免交错 staging/backup/rename 或删除他人 fallback。测试覆盖争用、dead-owner 恢复、token 保护、并发安装与无关文件/app 保留。
- daemon 单实例：锁由 daemon 自身持有（从端口探测前到 daemon.json 原子写入后），重复实例发现存活 daemon/竞态即退出；`single-instance-unit.ts` 用临时 home + 随机端口 + `BACKLIGHT_TRAY=0` 同时启动两个真实 daemon，断言恰好一个存活且 daemon.json 端口/pid 正确，另一个退出，关停后无 daemon.json/lock 残留。
- 附带：`isOurLauncher` 只认精确 bundle id；runtime 快照断言 canonical realpath 不逃逸、无 dangling symlink、`.pnpm/node_modules` dev hoist 已裁剪、删除源树后仍可加载运行时依赖。
