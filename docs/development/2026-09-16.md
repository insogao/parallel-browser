## Reviewer 第二轮复核 P1 修复（同日追加）

- **修复标志**：在向窗口发送 `normal` 之前设置 `windowTouched`；finally 的修复门槛不再依赖 `parked`。即使 normal 验证失败或 park 从未记录，只要仍是同一 cdp/pid 且未被 takeover，就执行 `original position → minimized` 的 best-effort 修复；读探针持续失败时仍发送恢复命令并 warn/计失败（与 setup 失败去重，避免同一事件双计）。
- **探针重试**：`waitForWindowState`/`waitForWindowPosition` 对单次 `getWindowBounds` 失败继续有界重试，只有 attempts 用尽、上下文失效或窗口消失才失败；新增 `readWindowBoundsBounded` 用于 cleanup/takeover 的多次重探。
- **normal 未就绪不再继续 setup**：抛出进入现有 catch，failure/cooldown 正常累计；finally 仍修复窗口。
- **takeover 清理**：单探针失败改为有界重探；仍不可读时 warn 并安全尝试恢复 original position，不会把窗口静默留在 offscreen。
- **新增确定性单测（红→绿）**：normal 后所有探针 reject → setup 不成功、cleanup 仍发送 original position→minimized、hidden app 恰好 re-hide 一次、无 controller/标题残留；normal 后单次瞬时 reject → 重试后 setup 仍成功。两项在旧源码上失败。
- **剩余风险**：capture 的 hide/unhide 不走 proxy 的 native 可见性队列（见 PROJECT_INDEX 能力边界）；`setPaused(true)` 等待 + cleanup 的 allowed/unhide 保证 `/api/show` 接管可见，但 capture 与 API 的 native 操作并发时无全局串行保证。手动移动窗口/Dock 恢复应经 `show` 路由，避免与 capture setup 并发操作同一窗口。

## Release-blocker 修复：显式 bg 的瞬时显隐（同日追加）

### 问题与证据

3. `chrome.tabCapture` 扩展路径无可见性门槛，可在最小化+隐藏时装定（rAF 100/s），但隐藏装定不产生 captured frames、CDP 截图（默认与 `fromSurface:false`）永久挂起；可见时装定后再最小化则真实帧/截图正常（21–38ms）。

## 显式可见性闸门（primary review blocker 修复，同日追加）

### 问题

Primary review 指出：`/api/show` 只把 auto/unknown 的 `maximize`/`activate` 降级，仍然执行 `restoreAll(false)` + `native.persist(false)`，即取消最小化/解除 AppKit 隐藏，仍会让浏览器重新可见；测试也仍然允许 unknown/auto restore。用户硬门槛是：**bg 之后任何非人类、非显式来源的重新出现（不只是“没最大化”）都是 bug**。此外托盘延迟到达的 `tray.auto.*` 在显式 bg 完成后仍可复现原始 2–3s 回弹。审计还发现 `/api/open` 在未运行时按 `settings.launchMode` 启动（visible 时可见）、`/api/extensions/dev` 未运行时同样继承 launchMode、`/api/launch` 在无显式 focus 时对非显式调用者同样继承 launchMode、`/api/inspect` 的 `newWindow:true`、`/api/restart` 与 `/json/new` 也能产生前台窗口。

### 策略（单一不可变量）

- **来源分类白名单**：只有已知控制面的 source 前缀才算 `explicit`（`cli.`、`dashboard.`、`tray.menu.`、`test.`、`probe.`）；`tray.auto.*` 与 `explicit:false` 为 `auto`；其余一律 `unknown`。调用方自报的任意 source 不再被当作人类证明，只作为日志 provenance。
- **只有 `explicit` 才能创建/恢复可见状态**：restore/unminimize、unhide、activate、maximize、visible launch 全部 exclusive；`auto`/`internal`/`unknown` 请求在任何副作用前被拒绝（不 bump 控制代际、不 noteIntent、不 restoreAll、不 native 操作）。
- **Dock 点击的诚实处置**：NSWorkspace activate/unhide 无法证明物理点击，因此 `tray.auto.*` 即使真实来自 Dock 也不再显示窗口；daemon 记录 `show-skip`（branch `unverified-activation`，并附当前原生证据 `evidence=hidden|active-visible|unhidden-inactive`），显式路径为托盘菜单“恢复窗口显示”、`bl show`、Launchpad/`bl login`。这是“无法验证就选安全（保持隐藏）”的用户指示。
- **真实物理点击保留性**：macOS/Chromium 自身的 Dock 激活行为不受 daemon 门禁影响；daemon 只保证不再由自动请求放大为“恢复所有窗口 + unhide + activate”。

### 路由审计与修复

| 路由 | 原行为 | 现策略 |
| --- | --- | --- |
| `POST /api/show|restore` | auto/unknown 降级 restore/unhide | 非 explicit 一律拒绝：auto 200 `ignored=unverified-activation/internal-activation/explicit-in-flight`；unknown 400 `ignored=unverified-source`；0 窗口/原生操作 |
| `POST /api/launch` | 非显式未带 focus 时仍按 `launchMode` | 非显式强制 `focus:false`/`keepVisible:false`；explicit 才可继承 `launchMode` 或 foreground |
| `POST /api/open` | 未运行时 `launchMode`（visible 可能可见） | 未运行首启固定 `focus:false` 后台；运行中保持 `background:true` |
| `POST /api/extensions/dev` | unknown 降级 restore/unhide | 非 explicit 400 零副作用；explicit 首启 `focus:false` 后显式 restore/activate |
| `POST /api/inspect` | unknown 降级 activate，仍 `newWindow:true` | 非 explicit 400 零副作用；explicit 才创建 DevTools 窗口 |
| `POST /api/restart` | 按 `launchMode` 重新启动 | 非 explicit 强制 `{focus:false}`；explicit 保持原语义 |
| `PUT /json/new` | 透传 Chromium，可能前台聚焦/建窗 | daemon 自行 `Target.createTarget({background:true})` 并返回同等 JSON，绝不聚焦 |
| `native.persist` | 非 explicit 仅降级 foreground，仍 unhide | 纵深防御：非 explicit generation 直接拒绝（记 `policy-downgrade/native-op`） |
| `/api/login`、`/api/console`、`/api/bg` | 已有 explicit 门禁 / 只隐藏 | 不变 |
| `/json/activate`、原始 CDP WebSocket | 可激活/操作窗口 | 维持“原始 CDP 客户端是高权限面”的既有边界，未纳入 provenance 门禁（残余记录） |

Tray 侧：observer 继续无条件上报 `tray.auto.*`（保持 OS 观测可追踪），但 `poll` 不再发自动 show（corner/第二实例）；仅保留“全部窗口已最小化时 `NSRunningApplication.hide()`”的保持隐藏逻辑。`BrowserManager.restartIfRunning` 作为内部助手固定 `{focus:false}`。

### 残余风险

- 物理 Dock 点击的“显示”现依赖 macOS/Chromium 原生 reopen（daemon 不再放大）；真实鼠标点击后的最终体验仍需人工验收，显式路径为托盘菜单 / `bl show` / Launchpad。
- 原始 CDP WebSocket 与 `/json/activate` 仍是高权限面（可自行操作窗口），与既有“原始 CDP 客户端”边界一致，本轮未改。
- 托盘 poll 的“全部最小化时 `NSRunningApplication.hide()`”仍由 tray 进程直接执行、不进 daemon state-log（只发生在窗口已最小化时，不产生可见状态）。
- 旧 runtime/旧 tray 进程仍按旧逻辑运行；需按既有“生效条件与安全步骤”`bl launcher install` + 在用户方便时重启 daemon/tray 后整体生效。
