## 本轮改动

1. 新增 opt-in 真实验收 `packages/daemon/tests/window-state-throttle.ts`：一个窗口状态序列（可见/最大化 → 最小化 → 恢复/最大化），capture 保活开启；采样输出区分 CDP windowState、AppKit hidden/WindowServer on-screen、`document.visibilityState`、timer、服务器网络轮询、补偿 rAF、原生 compositor rAF。SIGINT/SIGTERM 与正常结束共用清理：停 daemon、kill 隔离 profile 进程、删临时目录。
2. 新增 `tests/window-state-samples.ts` 与 `tests/window-state-throttle-unit.ts`（9 项纯单元）：转移时间戳、速率汇总、缺通道不算通过、阈值能区分 1 次/s 限流与 4 次/s 标称、以及注入脚本不得改写 `document.visibilityState`/`document.hidden` 的守卫。
3. `tools/app-control.swift` 新增只读 `windows <pid>`：CGWindowList 报告窗口总数与 on-screen layer-0 窗口数，供原生可见性交叉验证（无需辅助功能权限）。
4. `src/windows.ts` 新增 `maximizeWindow`：先有界等待 `normal` 生效再发 `maximized`，并校验最终状态；未验证成功的恢复不再计入 `restored`。`tests/windows-unit.ts` 新增 2 项确定性测试。
5. `src/capture.ts` 修复 capture 保活 setup 的窗口行为：park 拆成 `normal` 与位置两次调用（macOS 会忽略与 deminiaturize 合并的位置），记录实际生效位置；cleanup 先恢复原位置再最小化（位置作用在最小化窗口上会将其取消最小化）；新增可选依赖 `appHidden`/`hideApp`，由 `src/index.ts` 注入 `browserAppState`/`hideBrowser`，在 macOS picker 意外解除 AppKit 隐藏后恢复 `bg` 语义；takeover 时绝不重新隐藏。`tests/capture-unit.ts` 新增 2 项确定性测试（恢复顺序 + 隐藏状态；takeover 优先不隐藏）。
6. `package.json` 新增 `test:window-state` 独立命令；**未**加入 `test`/`test:integration` 默认链。新验收是手工 opt-in。

## 能力边界

- `document.visibilityState` 只读上报，capture 豁免下由 Chromium 决定显示值，不做断言也不改写。
- 补偿 rAF（shim）只证明页面逻辑帧，不代表原生合成帧；原生 compositor rAF 单独采集。
- 物理 Dock 点击与真实鼠标激活仍未自动化，待人工验收。
- capture setup 会短暂改变窗口状态（生产行为）；若最终 GUI 验收发现 AppKit 隐藏未恢复，应保留证据再修，不降级断言。
