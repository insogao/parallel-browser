# Backlight（后台浏览器）v0.1 实施计划

## 定位
对标 ego-lite 的功能与体验，但架构用「监督器 + 真实 Chromium 内核」，彻底解决 ego-lite 没解决的三个点：
1. **后台满速运行**：窗口最小化/收起后，页面照常渲染、rAF 不停、定时器不节流、截图不陈旧
2. **插件开发/测试友好**：一键加载未打包扩展、文件改动热重载、直达目标网站测试，扩展兼容性 100%（真实内核）
3. **AI 指令可视化**：AI 通过 CDP 操作页面时，页面上出现光环脉冲、菜单栏图标闪烁、活动流可订阅

## 产品名
Backlight（后台+高亮双关），中文名「后台浏览器」，CLI 命令 `backlight`（缩写 `bl`）。仓库就在当前工作区 `/Users/gaoshizai/work/ego`。

## 架构（TypeScript monorepo）
- **packages/daemon**（核心，常驻进程）
  - 启动/监督浏览器：探测本机 Chrome/Chromium/Edge（无则用 @puppeteer/browsers 下载 Chromium，不分发 Google Chrome）；每 space 一个受管 user-data-dir（登录态持久，对标 ego-lite 的 task space）
  - 启动参数（禁定时器节流三件套）：`--disable-background-timer-throttling --disable-renderer-backgrounding --disable-backgrounding-occluded-windows`
  - **窗口监督（核心机制）**：轮询 CDP `Browser.getWindowBounds`；检测到「真最小化」→ 立刻恢复为 normal 并移到屏幕外（伪最小化）。原理：rAF 停摆由"窗口隐藏"触发，启动参数管不了；而 Chromium 对未最小化的离屏窗口不判遮挡 → 页面保持渲染。全程 CDP 完成，无需任何系统权限。兜底：对确实隐藏的 target 用 `Page.startScreencast` 强制出帧（丢弃帧）
  - **CDP 代理**：固定监听 127.0.0.1:9333，HTTP(/json/*)+WS 字节级透传到真实调试端口，只读 method 字符串打点（不解析 payload，保证透明）→ 任何 AI 工具（Playwright `connectOverCDP`、Puppeteer 等）即插即用，同时我们能看到所有 AI 指令
  - 活动总线：CDP method 分类（Runtime.evaluate / Page.* / Input.* / Target.*…）→ 事件流广播（WS `/activity`）+ 环形历史
  - 页面光环：指令到达时向对应 targetId `Runtime.evaluate` 注入 0.8s CSS 发光边框（pointer-events:none，可在设置里关）
  - 扩展管理：注册表（extensions.json）→ 拼装 `--load-extension`（可选 `--disable-extensions-except` 独占模式）；chokidar 监听扩展目录，改动防抖后自动重启浏览器并恢复 CDP 记录的标签页
- **packages/cli**：`backlight launch|bg|restore|open <url> --with <ext>|ext add/ls/rm|space ls/use|status|activity|doctor|stop`
- **packages/tray**：菜单栏应用（Electron 仅做托盘与面板，规避 Xcode 依赖；M0 若发现有 Xcode 可改 Swift 小程序）。空闲=常亮、AI 活动=闪烁、后台任务=呼吸；「一键收起全部到后台」菜单项 + 全局快捷键
- **packages/dashboard**：daemon 内置网页（http://127.0.0.1:9333/）：实时活动流、各标签页节流健康度（daemon 周期性注入 rAF/定时器计数器并读回）、扩展与 space 管理
- **packages/agent**：薄 SDK + 中文文档（snapshot/evaluate/screenshot/click 少量 helper，其余引导直接用 Playwright 连 9333）

## 里程碑与验收
- **M0 环境核验与脚手架**（plan mode 里 Bash 被禁，未完成的检查在此补）：node/npm 版本、浏览器探测、npm 源连通性（不通则切 npmmirror）、Xcode 有无（决定 tray 实现）；建 monorepo，daemon 骨架跑通
- **M1 后台满速（核心1）**：先做验证 spike——测试页带 rAF/定时器/网络计数器，矩阵实测：前台/遮挡/切 Space/真最小化/伪最小化 × 参数开关，确定伪最小化是否成立；不成立则按 fallback 链（screencast 保活 → 1x1 置底窗口）。验收：伪最小化 5 分钟 rAF 计数持续增长（≥前台 95%），CDP 截图非陈旧帧；健康度上 dashboard
- **M2 插件开发循环（核心2）**：ext add/rm/ls、热重载、`open <url> --with <ext>`。验收：MV3 declarativeNetRequest 扩展行为与原版 Chrome 一致；改 content script 后 ≤3s 生效；测试用例脚本化（npm test 可重复验收）
- **M3 AI 指示器（核心3）**：代理打点 → 光环 + /activity + dashboard 实时视图。验收：Playwright attach 后执行点击，光环与活动流即时可见；代理与直连真实端口行为无差异
- **M4 托盘与收起体验**：托盘三态图标与闪烁、全局快捷键一键收起/恢复、dock badge（我们的 app 自己的图标，可以合法地闪）
- **M5 对标打磨**：多 space、doctor 体检（环境/健康度/回归测试页）、中文 README 与使用文档、`npm i -g` 安装与可选 .app 壳，发 v0.1.0

## 风险与对策
- 离屏窗口是否被 Chromium 判 hidden 未实测 → M1 第一个实验，带两级 fallback（screencast 保活、1x1 置底窗口），任一可兜底
- Chrome 大版本变更 → 只依赖 3 个长期稳定的官方开关 + 公开 CDP 协议；doctor 内置回归测试页可随时复验
- CDP 调试端口安全 → 仅绑 127.0.0.1，代理可加 token 门禁
- Electron 二进制下载可能被墙 → M0 检测并预设 npmmirror 镜像

## 不做的事（v0.1 明确排除）
自研浏览器 UI（那是 fork Chromium 的路线，已按你的决策排除）、Chrome Web Store 商店扩展的自动安装（可手动拖入 crx 解压后 add）、Windows/Linux 支持（先 macOS）。
